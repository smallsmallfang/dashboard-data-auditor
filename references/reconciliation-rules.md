# 核对规则与差异桥接

| 检查 | V0.1自动执行 | 额外证据/人工任务 |
| --- | --- | --- |
| 口径可比性 | 校验明确声明的scope；不一致时阻断 | 业务确认、SQL及平台报表定义 |
| 缺列/空关键字段/数字/日期 | 是，拒绝把未知填零 | 导出范围和原始格式 |
| 重复 | 按来源声明的unique_key检查 | 主键本身是否真正表达行粒度 |
| 漏数 | 双方分组并集的单侧缺失 | 双方同时缺失须对照完整范围清单 |
| 汇总与明细差异 | 共有粒度逐组及总计 | 更细明细无法由粗粒度导出恢复 |
| 利润复算 | 用户声明的同币种线性公式 | 成本、费用、退款、积分组成的经济定义 |
| SQL连接放大 | 通过重复/异常发现线索 | 连接前后行数、唯一键数和金额守恒 |
| 费用重复/缺失 | 非自动根因识别 | 费用交易唯一ID、实际/预估标记与更新记录 |
| 分摊守恒 | 尚未自动实现 | 费用池=已分配金额+未分配余额，保存映射 |
| 汇率方向/成本版本 | 元数据门禁，不计算兑换 | 来源币种、目标币种、汇率日期、方向及原金额 |
| 销售vs结算桥接 | 阻止误用等式；模板辅助 | 逐交易证据、日期跨期和政策差异 |

## 不同口径的桥接

1. 确定要解释的目标：例如销售口径利润与结算口径利润，而不是先假设必须相等。
2. 以可追溯的订单/交易集合分出：仅销售侧、仅结算侧、双方共有但金额不同。退款、撤销、补记按真实经济事件单独记录，不能简单用同SKU关联多条费用。
3. 每条桥接调整保存唯一证据号、来源行、指标、带符号金额、适用期间和待确认/已确认状态。一个差异不能被多个原因重复解释。
4. `预计目标 = 起点金额 + 已确认调整之和`；`未解释残差 = 实际目标 - 预计目标`。未解释残差不能重命名为“其他时间差”。
5. 有残差不直接判定业务错；没有残差也不代表证明了根因。检查证据覆盖和非重复性。

模板在 `assets/bridge_template.csv`。桥接模板不被当前CLI自动消费，不声称已实现自动桥接。

## 验收与负责人说明

底数问题先定位产生差异的链路，再由数据团队排查。口径问题由业务Owner组织规则确认，但不能自动认为“口径问题不影响上线”。是否可用要按指标风险和使用场景决定。

领导反馈模板：

> 本次核对了[范围]的[来源→来源]。已确认[事实及证据]；对[指标/决策]存在[影响]。目前[可用范围]可供参考，[不可用范围]暂不用于决策。请[建议责任方]补充[明确证据/修复结果]，完成时间待认领后约定。
